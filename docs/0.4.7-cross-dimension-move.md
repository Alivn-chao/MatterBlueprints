# 0.4.7：MM 跨维度移动

适用于 GTNH 2.9.0-beta-3 / Matter Manipulator 0.1.55-GTNH。客户端和服务端都安装 0.4.7；不需要替换 MM 本体。

## 使用

1. 用支持移动的 MM（MKII / MKIII）切到原生移动模式，在源维度标记剪切 A、B。
2. 保持源区域区块加载，前往目标维度，使用 MM 原生菜单标记目标 C 并确认位置。
3. 青色线框表示目标范围。目标 C 对应源角点 A，即使 A 在 B 的正方向也不改变锚点。
4. 保持手持这把 MM，在空中持续潜行右键开始移动。松开即暂停；重新执行会跳过源处已搬走的空气，继续搬剩余方块。

两端必须是已经加载的维度和区块；插件不会自动生成或强制加载远端地形。MKII 保留 128 格目标操作范围，MKIII 沿用原生无限范围。区域轴长、体积使用现有 `limits.maxSpan` / `limits.maxBlocks` 配置。

## 行为

- 这是方块实体搬运，不是蓝图复制。读取源维度的实际方块，交给 MM 原有搬运器处理普通方块、机器和 TileEntity 数据；成功后源处变为空气。
- 按两端实际世界分别触发 MM 原有破坏、放置权限检查；保留原生 TeleposeEvent、掉落捕获与搬运器钩子。不可破坏方块、受保护方块与被占用的实体目标会跳过，源方块保留。
- 跨维度移动不会覆盖目标实体方块，即使移除模式为 ALL。请先清出目标空间。草等可替换方块仅在允许移除时清理；缺少支撑的源方块暂缓重试，无进展时暂停。
- 速度、加速升级、供电补充、节能升级继续使用 MM 原生机制。单块基础能耗沿用原生硬度与 TileEntity 倍率，距离按玩家到目标位置计算，避免将两个维度无关的绝对坐标当作远距离耗电。
- 队列按游标增量扫描，每次扫描最多 4096 个位置，实际移动数不超过 MM 原生每批上限。只为缺少支撑或缺电重试的位置排队，不预先展开整个选区。
- 客户端仅显示目标范围框，不尝试读取客户端不存在的源维度地形。工具提示显示源、目标维度编号。
- 同维度移动继续交给 MM 原生处理。外部网络或跨机器地址的可用性沿用各模组自身规则，不保证搬到另一维度后原有外部连接仍然有效。

通过几何、边界及原生队列/Forge 事件顺序兼容测试；尚未在实际服务器中验证跨维度机器、保护插件及光影组合。
