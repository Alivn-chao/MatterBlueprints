# 0.4.20：MM 复制继承托管绑定

目标环境仍为 GTNH 2.9.0-beta-3 / Matter Manipulator 0.1.55-GTNH / GregTech 5.09.54.133。

## 使用方式

- 已绑定的多方块控制器通过 MM 复制、旋转、镜像或阵列粘贴后，新控制器自动绑定到**原来的托管中心**。GTBP 蓝图也保存这份关系。
- 复制选区应包含机器控制器。只复制外壳、能源仓等结构方块不会生成新绑定。
- 中心下一轮扫描接管新机器，默认间隔 100 tick（5 秒）。机器仍须成型、类型与中心选择器一致并满足原有供电条件。
- 只复制绑定关系，不复制正在运行的配方、预付电量、燃料、产物或里程碑。
- 原中心未加载时可以记录绑定，加载后接管；不会为此强制加载区块。
- 拆除机器控制器时删除绑定；原中心当时未加载也会记录删除。拆除外壳导致机器暂时不成型不会解绑。
- 拆除托管中心会删除其全部绑定。重新放置在相同坐标的是新中心，旧蓝图不会误绑过去；控制器物品保留里程碑的旧功能不变。
- 区块卸载、维度卸载和正常重启不会解绑。已绑定其他中心的目标不会被复制操作抢走，MM 会提示无法继承绑定。

客户端、服务器同时替换为 0.4.20。旧存档中的中心加载后自动迁移绑定，不需要逐台重新扫描。升级后先让原中心加载并完成一次扫描，再复制；升级前导出的蓝图没有绑定信息，需要重新保存。

## 实现与性能

`HostedBindingData` 使用世界级持久化索引记录中心身份、中心坐标及机器归属。中心身份不写入控制器掉落物，因此拆掉重放不会重新接管旧设备。

MM 的 GT 分析结果仅附加中心身份字段，在分析、克隆、相等性判断、JSON 保存与实际应用过程中保留。实际绑定只在成功应用 GT 属性后执行；材料规划和客户端投影不修改绑定。重复粘贴是幂等添加，不会像绑定器一样切换解绑。

拆除钩子位于 GT `BlockMachines.breakBlock`，避开可被取消的挖掘事件及区块卸载。索引立即更新，运行任务容器在安全的 tick 边界清理，避免原机运行回调触发拆除时修改正在遍历的集合。持久化索引优先于中心的旧区块 NBT，防止卸载期间拆除的机器重新出现在绑定列表中。

复制和拆除使用哈希索引定位，不遍历世界机器；周期同步复用已有中心扫描间隔。

## 验证

- 128 台阵列复制、重复应用和不同中心归属冲突。
- 跨维度绑定存档往返；中心未加载期间拆机，中心旧 NBT 不能恢复已删除关系。
- 拆源机器保留其副本，拆中心撤销全部关系；同坐标新中心拒绝旧身份。
- 旧绑定一次性迁移、移除机器清理保存的任务、掉落物不携带绑定身份。
- MM 克隆回调、JSON 旧格式兼容、相等性及安装版本的原生方法签名检查。
- `gradlew build --offline` 完整构建、Checkstyle 和 261 项测试通过。已核对拆除钩子的生产环境 SRG 映射；未在实际游戏存档中执行联机粘贴测试。
