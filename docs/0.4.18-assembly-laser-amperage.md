# 0.4.18 进阶装配线激光超频安培修复

## 问题

进阶装配线在能量里程碑 3 阶以前使用激光超频。旧托管代码给计算器设置了 `laserOC=true`，却同时设置 `amperageOC=false`。GT 的超频计算器会因此把可用安培截断到当前并行数；一份配方即使配置 UMV 65536A，也可能只按约 1A 算超频。

用户截图中能量等级 2、当前并行 1、耗电约 9.44×10^7 EU/t，与 125,829,120 EU/t 配方应用 ×0.75 耗电加成后的结果一致，说明高安培未用于额外激光超频。

## 修复

- 激光超频同样启用总安培参与计算，同时保留按电压等级限制普通超频次数、超过部分使用递增激光能耗惩罚的规则。
- 能量 3 阶切换普通超频，6 阶切换无损超频的门槛保持不变。
- 普通装配线的原有电压超频规则保持不变，在实际规划入口仍明确禁用安培超频。
- 保留远端能源仓电压、安培和功率预算检查、输入扣除、批处理及不足 1 tick 的超频收益，以及 0.4.17 的空闲容量调度修复。

高安培能源仓需要安装在被托管的进阶装配线上；仅给中心增加能源仓能力，不会改变远端机器的超频参数。

## 验证

新增回归用例在修复前复现了同级 UMV 65536A 不增加超频次数的问题，修复后通过。

测试直接调用当前依赖 GT 5.09.54.133 的 `OverclockCalculator` 和 `ParallelHelper`，覆盖同电压 1A 与 65536A 对比、只投一份配方且开启批处理、激光递增能耗惩罚、低于 1 tick 的收益、批处理追加与只扣一次原料。使用 125,829,120 EU/t、480,000 tick、耗时 ×0.75 的截图数值模型；配方物品使用测试替代物，并非完整游戏世界重放。

客户端与服务端同步替换为 0.4.18。已经扣料开始的任务保留其原始进度与耗时，新启动的任务使用修正后的超频计算；无需重新绑定或清空里程碑。尚未进行游戏内复测。
