# 聚变机器托管（0.3.22-beta3）

## 0.3.22 修正（取代下文旧版开机费规则）

托管中心没有聚变预充能缓冲，因此取消托管配方的开机费，首次和后续均不扣除启动 EU。原机开机容量仍用于配方等级检查，持续运行 EU/t 正常消耗。

修复普通／进阶聚变被原生设置锁在单机 1A 的问题：聚合安培按托管数量增加，保留单机电压和原生超频规则，并受中心实际供电预算限制。原生超频描述器重写的电压也会重新受中心预算约束。相同条件下，2、4、5 台机器不再共用单机功率上限；实际产能仍受配方、输入和输出限制。

修复已弃用 `addOutput(FluidStack)` 固定返回 false 导致的“部分产物无法输出”误报，改用实际剩余流体数量判断。聚变产物堵塞时保留未输出数量并重试，不丢产物、不重复输出已交付部分；等待输出期间不再扣运行电费。

新增 2／4／5 台功率缩放、部分输出重试和零开机费回归测试。尚未在用户存档中实测镄等离子配方。

适配 GT 普通聚变 MK I–III、GT++ 进阶聚变 MK IV/V，以及 Good Generator 大型聚变 I–V（含对应派生型号）。

## 0.3.21 历史开机费规则（已取消）

- 同一托管中心保持绑定期间，首次成功启动聚变配方时，从中心扣除该配方 `FUSION_THRESHOLD` 指定的一次开机费，不乘以并行数量。
- 原料、输出容量与超频功率检查先完成，再扣开机费和配方输入。开机费不足时，不消耗原料，也不记录已支付。
- 连续生产、切换可运行的聚变配方、缺料等待及存档重载均不重复扣费。取消中心全部绑定后，重置首次启动状态。
- 有线模式从中心能源仓的实际存量扣费；无线模式从中心对应的无线账户／预付余额扣费。开机费不受每 tick 吞吐量限制，也不重复叠加到配方 EU/t；其实际支出计入能量里程碑，不增加工作时间。
- 持续生产仍按每 tick 功耗供电。首次开机费支付后，中心需要继续补足运行电量。

## 原生规则

已支付开机费不解除聚变等级限制：每个配方仍检查原机的开机能量容量，容量不足的低级聚变不能运行高级配方。容量在扩展托管并行之前读取，不因聚合其他机器的能源仓而提高。

保留各型号原生聚变超频描述器，包括进阶聚变本身的无损超频。大型聚变按配方原生 `getMaxPara × extraPara` 计算基础并行，再叠加托管并行增幅，受中心功率和输入输出约束。

同一组聚变须为相同型号、相同原生开机能量容量。聚变原料与产物通过托管中心输入输出，结构仍须保持成型。

自动测试覆盖一次扣费、余额不足保料、存档恢复及原生 ParallelHelper 的延迟投料；游戏内结构和服务器重载仍需实测。
