# 化工厂中央催化剂仓（0.3.6-beta2）

## 用法

1. 在托管中心原本允许安装仓室的机房外壳位置，换入 GT++ 的“催化剂仓”。不能替换灯带、风扇、地板等固定结构位置，且须保留最低外壳数量及原有必需仓室。
2. 把配方要求的催化剂放进中央催化剂仓。可安装多个催化剂仓；普通输入总线中的催化剂不作为授权来源。
3. 托管中心放入化工厂控制器物品并绑定已经成型的远端化工厂。远端无需放置催化剂；原版化工厂的催化剂仓本身是可选结构部件。
4. 原料、产物、电力继续走托管中心。远端保留原有成型条件和用于定义电压的能源仓。

托管期间催化剂不消耗、不增加耐久损伤，也不生成空催化剂载体。中央仓内同一种催化剂可以供整组聚合任务使用，不需要按机器数量准备。

同一中心的化工厂必须具有相同的外壳、机械方块、管道、线圈等级及电压；不一致时会阻止新任务并给出中文提示。这避免聚合时把代表机器的配方资格和速度加成错误地用于不同等级机器。

催化剂只在每次开工时检查，移除后不会取消已经投入原料的任务，但下一次开工必须重新满足条件。无催化剂要求的配方不强制安装催化剂仓。

## 范围与实现

- 适配 GT5-Unofficial 5.09.54.132 的 GT++ Chemical Plant。
- 只在托管配方检查期间临时替换 ProcessingLogic，正常运行的化工厂仍遵循原版损耗机制。
- 保留原化工厂的 setupProcessingLogic，因此不修改线圈速度、正常功耗计算或机器等级字段。
- 缓存托管配方逻辑以保留配方缓存；按开工时的中央催化剂快照匹配，不在每个 tick 重复扫描仓室。
- 配方检查结束后（包括失败/异常路径）恢复原 ProcessingLogic。聚合并行、批处理和已有进度流程继续复用。

## 游戏测试清单

- 客户端与服务端都换成 0.3.6-beta2，旧版 JAR 禁用；先备份存档。
- 中央催化剂仓使结构成型，底色融入深色机房外壳。
- 远端催化剂仓留空，只在中央仓放正确催化剂，多台同配置化工厂正常聚合。
- 连续执行及批处理后中央催化剂数量、NBT 耐久不变，无额外空载体产出。
- 错误/缺失催化剂不能开始对应配方；仅在普通输入总线放催化剂也不能绕过。
- 机器等级不足不能越级，混合等级提示配置不一致。
- 移走催化剂，当前任务完成但下一次需重新检查；重新放入可以恢复。
- 重启读档、解绑后原化工厂的独立运行机制不变。

自动化单元测试及构建不代替游戏内成型、AE 输入和专用服务端测试。
