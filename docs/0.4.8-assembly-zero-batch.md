# 0.4.8：装配线批处理追加零次导致关机

适用于 GTNH 2.9.0-beta-3 / Matter Manipulator 0.1.55-GTNH。

## 原因

服务端日志记录托管中心 32600 抛出 `IllegalStateException: Assembly inputs changed before commit`，调用路径为 `ParallelHelper.determineParallel:523` → `HostedAssemblyRecipe.consumeInput`。

开启批处理且超频后耗时较短时，GT 在常规并行的模拟扣料之后继续计算追加批次。如果剩余原料不足以追加一轮，追加次数为 0；GT 仍调用 `consumeInput(0, ...)`。此前装配线包装器将该调用传给只接受正并行的材料规划器，误判成原料发生变化并抛出异常，触发 GT 的崩溃关机。

这不是进阶防辐射板或另一条截图配方的单独注册问题，满足同样条件的其他托管装配线配方也可能触发。

## 修复

`HostedAssemblyRecipe.consumeInput` 对零次调用直接返回，不读取或修改材料。正数调用仍完整验证材料并一次性提交；真实缺料仍会拒绝，不屏蔽异常或跳过材料检查。原生批处理、超频、产物与防串配方逻辑继续沿用。

新增回归测试覆盖：

- 61,440 EU/t、1,000 tick、1,152 L、七种物品的配方参数，在超频、加速、开启批处理且原料恰好一轮时不再异常。
- 7,864,320 EU/t、400 tick、256,000 L 的高压配方参数，同样覆盖零次追加。
- 空材料的零次扣料为无操作；正数缺料仍拒绝且不部分扣除。

前两种场景使用原生 GT `ParallelHelper`，修复前复现同一异常；修复后检查规划阶段原材料不变、产出一份、最终提交仅扣一次。测试使用替代物品表达截图的数量结构，不依赖完整整合包注册，也不等同于实际服务器复测。

更新客户端与服务端后，手动重新启用已关机的托管中心即可继续验证。
