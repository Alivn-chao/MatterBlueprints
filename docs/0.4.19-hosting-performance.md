# 0.4.19 大量托管性能优化

针对 32 台大型硅岩反应堆、无线发电的反馈，减少每 tick 的重复操作，同时保留原有结算规则。目标环境保持 GTNH 2.9.0-beta-3 / GregTech 5.09.54.133。

## 修改

- 已结清整批时空/液空辅料的硅岩周期，不再每 tick 创建输入输出仓室快照、创建动力舱快照并读写动力舱电量。这些操作只在调用原生辅料扣除机制时执行。
- 无线硅岩发电不再扫描动力舱吞吐，因为它原本就不受该吞吐限制；有线发电仍实时检查原有输出限制。
- 同一中心、同一 tick 的硅岩无线发电合并入账：32 台就绪反应堆从 32 次无线入账变为 1 次，不把多 tick 的能源缓存到以后才发。每台仍保持各自的能量余额、60 秒时钟和完成输出。
- 入账失败时，所有相关周期都不扣能量、不前进；暂存请求在当 tick 清除，下次重新提出。入账成功后，先结算所有周期，再执行原生污染与完成输出回调，防止某个回调异常使其他周期的已入账能量被重复发放。
- 无线周期用缓存的商与余数计算每 tick 产能，结果与原来的 `剩余能量 / 剩余 tick` 逐 tick 完全一致。存档格式不变，重载或部分入账后会重建缓存。
- 普通托管在没有额外任务时，查询任务不再复制整份列表；发电中心每 tick 更新显示代表机，后续界面查询可直接取当前任务。
- 远端已经禁用/已停止激活时，不再重复发送对应状态写入；仍逐 tick 检查远端状态。
- 无线升级判断复用物品注册表参照，避免每次调用 `ItemList.get(1)` 都复制一个物品堆。

未降低游戏逻辑 tick 频率。维护检查、辅料扣除、能量总额、产物、污染、里程碑和掉线恢复继续按原有规则运行。涡轮等其他原生发电机保留自己的运行与磨损回调；没有直接套用硅岩专用的轻量路径。

## 验证与测量边界

新增测试覆盖：32 台 ×1200 tick 的精确总能量、每 tick 仅一次入账、异步起始进度与重载、整 tick 入账失败、回调异常后的防重复发电、零输出 tick、未付费请求清理，以及缓存算法在随机大整数、重载和部分入账时与逐 tick 除法的一致性。既有有线末 tick 余量、超 long 能量、旧任务恢复、批处理与超频测试继续运行。

截图平均约 73,724 ns/tick，即 0.073724 ms/tick，仅凭扫描器数值不能定位所有热点。尚未在该存档中做优化前后对比，因此不承诺整台中心或服务器 TPS 的具体改善比例。

独立微基准只测量 `HostedNaquadahCycle.nextOutput/accept` 加总输出的计算与分配，不包含游戏世界、原生回调或网络。相同 Java 25.0.1、256MB 初始/512MB 最大堆，预热后 7 次取中位数；每样本为 32 台 ×1200 tick ×32 批次：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 样本耗时 | 45.096 ms | 26.879 ms |
| 当前线程累计分配 | 330.728 MB | 177.422 MB |
| 输出总量校验 | 1024000000000000000000000000730112 EU | 完全一致 |

该微基准中耗时约降 40%，分配约降 46%；不能据此说整个托管中心也下降同样比例。源码在 `tools/NaquadahBenchmark.java`，本次原始输出在 `build/hosting-perf-before/result.txt` 和 `build/hosting-perf-after/result.txt`。

## 更新

客户端和服务端同时替换 0.4.19。无需重新绑定、清空运行任务或重置里程碑，现有已付费硅岩周期直接兼容。包含 0.4.17、0.4.18 的装配线容量与激光超频修复。本次不包含检查记录中尚待处理的纳米煅炉等机器的耗时/并行覆写适配。
