# 跨配方并行（0.3.23-beta3）

托管中心可同时推进不同配方。每份任务独立保存耗时、进度、EU/t、并行数及待输出物，短配方完成后释放额度，无须等待长配方结束。

`config/matterblueprints.cfg` 的 `hostMilestones.crossRecipeTasks` 默认 64，范围 1–1024。普通配方跨配方任务不再由旧的任务里程碑限制为初始 1 份；总并行仍遵守机器与并行里程碑，电压、配方条件、中央电量预算仍须满足。并行上限只有 1 时不能同时运行两份任务。

候选配方来自中心普通输入及双输入仓／ME 缓冲的独立库存；实际扣料仍通过原机配方逻辑。各配方共享剩余并行和电量，调度时给其他候选配方预留电量，避免第一份任务占用全部功率。只有一种配方时仍能使用完整额度。

普通无自定义工作 tick 的机器，可在同一原机上保存多份独立任务。带独立工作 tick、热处理预热、等离子煅炉状态的特殊机器，维持每台原机一份任务，多台原机可同时执行不同配方。装配线仍沿用单独的数据仓配方调度与任务里程碑。

输出堵塞时保留剩余产物，等待输出期间不扣工作电量。额外任务随中心存档保存；原机不可用时暂停，解除绑定不会把已投料的额外任务丢弃，重新绑定同一位置可恢复。

参考 GTNL dev-290 的 [WirelessEnergyMultiMachineBase](https://github.com/ABKQPO/GT-Not-Leisure/blob/dev-290/src/main/java/com/science/gtnl/common/machine/multiMachineBase/WirelessEnergyMultiMachineBase.java) 中反复检测配方、递减剩余并行、累计输出的方式。托管中心使用独立逐 tick 任务，保留有线供电支持与不同配方独立完成时间；不依赖安装 GTNL。

自动测试覆盖共享供电预算、同机多任务独立存档和单任务完成不清除其他任务。尚未进行整合包内实测。
