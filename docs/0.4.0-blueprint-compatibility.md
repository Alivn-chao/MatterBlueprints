# 0.4.0：真空传送管道与 GT 框架蓝图兼容

目标环境：GTNH 2.9.0-beta-3、GTNewHorizonsCoreMod 2.9.61、Matter Manipulator 0.1.55-GTNH。
产物：`build/libs/matterblueprints-0.4.0.jar`。客户端、服务端均替换旧版 Matter Blueprints，避免重复安装。

## 修复内容

- 保存及加载蓝图时，将旧式 GT `MTEFrame` 对应到相同材质的当前框架物品。规划和搭建共用转换后的物品，避免请求隐藏的旧机器物品。
- 框架保留完整材质编号，剔除表示方块实体的高位标记；不使用仅适用于普通方块的 0–15 元数据范围。配置机替换物品也使用相同转换。
- 真空传送管道以普通管道物品作为材料，颜色单独存储和恢复，不要求库存提供带颜色的管道物品。
- 放置真空管时先恢复颜色，保留目标位置的连接状态，由真空网络重建连接，避免将旧位置的连接强行应用到新邻居。
- 染色框架即使没有覆盖板，也会创建保存颜色所需的方块实体，再恢复颜色、覆盖板等 GT 配置并同步显示。
- 保留之前的装配线样板目标匹配、普通装配线升压、批处理和不足 1 tick 超频修复。

已有蓝图包含框架和颜色信息时，会在创建搭建任务时自动转换；若旧文件已漏掉框架或颜色，无法凭空恢复，请从原结构重新保存蓝图并重新生成缺失计划。

## 验证范围

自动化测试覆盖多种完整材质编号及实体标记、旧框架物品转换、全部 16 种颜色及未染色管道的材料一致性、颜色持久化、无覆盖板染色框架初始化，以及真空管恢复时保留目标连接。放置测试使用隔离的世界与 GT 状态替身，不代表完整整合包实测。

完整构建、代码检查与 127 项自动化测试通过。仍需在实际存档中复测背包/AE 取料、缺失计划及真空网络连通性。
