# 0.4.13：无线频道界面导致服务器崩溃

环境不变：GTNH 2.9.0-beta-3 / GregTech 5.09.54.133 / ModularUI2 2.3.88-1.7.10。

## 原因和修复

用户报告的异常发生在 `PanelSyncManager.detectAndSendChanges`：正在遍历的同步表中出现空处理器，导致玩家 tick 异常并停止服务器。

0.4.12 的频道列表使用频道 UUID 作为同步器注册键。新增频道或翻页时，动态控件会在 MUI 遍历同步表的过程中增加处理器，触发底层表扩容，破坏遍历。已有频道在打开界面时也会注册同类动态处理器。

0.4.13 在界面创建时只注册一个固定的频道操作处理器。动态行不再注册任何处理器；点击时发送操作类型与频道 UUID。服务端校验操作类型、UUID、玩家权限和频道归属，再执行连接、收藏或删除。列表刷新、分页和计数变化均不改变同步表。

保留 0.4.12 的客户端点击隔离、控制器主界面使用 PosGuiData 玩家和渲染修复。

## 界面质感与交互

按照用户补充的 GTO 参考图，替换原来的平涂矩形：

- 面板使用金属灰渐变、外侧暗边、内侧高光和底边阴影；金棕色节点标题及黑色状态框采用内凹边框。
- 青色新建、红色断开、分页和频道操作按钮均有立体斜边及细高光。悬停变亮，按住时反转明暗形成凹陷，同时文字或图标偏移 1 像素；离开按钮或松开后恢复。保留 MUI 点击音效。
- 名称输入、新建和断开放在同一行，缩短无用留白；频道卡片名称靠左，下方显示计数，右侧为收藏和删除。
- 所有交互反馈在客户端本地完成，不会在列表重建时注册服务端同步器。

外观由 MUI 绘制，无须增加资源包。

## 验证

- 使用 beta3 同版本 MUI 的真实 PanelSyncManager，在测试中复现旧注册方式触发的相同空指针异常。
- 使用真实同步表遍历和动态控件重建，覆盖已有频道时初始化、10 次界面开关和 640 次不同内容的列表刷新；包括空列表及每页最多 32 个频道。修复后的注册表始终为固定数量，且没有未注册的行控件处理器。
- 使用真实 PacketBuffer 检查三种频道操作的数据包、客户端不执行服务端动作，以及无效操作/UUID 被拒绝。
- 完整构建、Checkstyle 和全部测试通过。

测试覆盖界面同步生命周期，不等同于在完整整合包和用户服务器内的运行验证。

## 安装

停止服务器后，将服务器和客户端的旧版 matterblueprints JAR 替换成 0.4.13，再重启。保留原有存档和配置，不需要删除控制器、频道文件或玩家数据。两端不要同时留多个版本。
