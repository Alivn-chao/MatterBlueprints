# 0.4.21：面向 128 台托管的性能优化

保持 GTNH 2.9.0-beta-3 / MM 0.1.55-GTNH / GregTech 5.09.54.133 兼容。

## 改动

- 附加配方任务通过已接管机器索引取得控制器，省去每 tick 的坐标字符串拆分、整数解析及世界方块实体查询。接管、释放、卸载、拆除时维护索引；不会为查询加载区块。
- 主任务与附加任务使用只读迭代视图，统计运行数、并行占用和电量预留时不再复制整份任务列表。每次遍历仍读取最新任务和绑定状态。
- 普通机器一轮配方调度只计算一次总并行容量，而不是每接纳一个任务再遍历全部机器。下一轮调度重新计算，保留配置与里程碑更新。
- 多台机器交替执行原生运行回调时复用临时上下文；电量字段仍在每次调用的 finally 中恢复。
- 热力机器反射字段及机器类型按实际 Java 类缓存。只缓存字段元数据，不缓存线圈、玻璃、燃料减免、热量等值；每台机器仍独立读取和更新自己的状态。
- 发电任务已全部运行、或空闲任务还没到原有重试时间时，跳过两轮空闲涡轮/新任务调度遍历。正常完工仍可在当 tick 接下一批，包括无线结算回调中完工的硅岩任务。
- 无线硅岩发电已经不受动力舱总吞吐限制，刷新中央功率时不再先遍历全部远端动力舱、计算随后会被无限上限覆盖的总量。有线发电及其他受限发电类型仍按原规则计算。

没有通过降低配方、发电、污染或特殊原机回调的执行频率来省时间。里程碑的任务数、并行解锁规则不变；本版也不包含尚未完成的纳米锻炉速度/并行覆盖修复。

## 验证

完整 `gradlew build --offline --console=plain` 成功，Checkstyle 和 **264 项测试**通过。

将无线批量结算回归提升到 **128 台 × 1200 tick**，验证大于 long 的总能量严格守恒、每台均完成 60 秒结算、总共只向无线账本写入 1200 次。另有交错进度、停电拒绝入账、存档重载和回调异常的原有回归。

新增只读任务视图的 128 台及附加任务过滤测试、解绑/列表变动/独立迭代器测试，以及反射缓存读取实时值、不同实例和子类同名字段的测试。

## 局部对照基准

`tools/Hosting128Benchmark.java` 对照 0.4.20 的字段查找与任务列表复制方式，Java 25.0.1，256–512 MB 堆，预热后 7 次取中位数。计时和线程累计内存分配结果如下，前后计算校验值一致。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 128 个模拟对象，200 轮读取继承字段 | 8.596 ms / 18.637 MB | 0.126 ms / 约 0 MB |
| 128 主任务 + 128 附加任务，2 万轮遍历 | 29.404 ms / 51.360 MB | 25.776 ms / 1.920 MB |

这里的 ms 和 MB 是整段基准的累计时间与累计分配量，**不是每 tick 指标，也不是整个服务器的优化比例**。字段基准使用模拟继承字段，不能代表所有原机的字段分布。结果不包含世界、GT 原机 tick、ME 网络、配方查询、真实输入输出及其他模组开销。

128 台机器的实际 MSPT 需在相同存档、相同配方、相同投料与区块加载条件下对照。尤其应分别观察稳定运行和集中开工/出料时的峰值；本版不能保证所有机器类型具有相同收益。
